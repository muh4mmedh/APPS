# Android build

Wraps the whole collection — the launcher and every app — in a WebView, so one
APK holds all of them. Adding an app to the repo puts it in the next build with
no changes here.

## Building

```sh
cd android
./gradlew assembleRelease
```

The APK lands in `app/build/outputs/apk/release/`. You need a JDK 17+ and the
Android SDK (platform 34); Android Studio provides both, or set `ANDROID_HOME`
to an existing SDK. The web files are copied into the APK automatically on
every build, so they can never go stale.

To install over USB:

```sh
./gradlew installRelease
```

## The one detail that matters

The pages are served from `https://appassets.androidplatform.net/` through
`WebViewAssetLoader`, not from `file://`.

This is not cosmetic. `getUserMedia` — the camera — is only available in a
secure context, and `file://` is not one. A `file://` WebView looks like it
works right up to the point someone tries to scan a cube, and then fails with
no useful error. Serving the same files over that https host makes the page a
secure context while everything still comes out of the APK, with no network
involved.

Two further pieces are needed for the camera to actually work:

- `CAMERA` in the manifest, requested at runtime when first needed
  (`MainActivity` holds the `PermissionRequest` while Android asks, then grants
  or denies it once the answer comes back).
- `WebChromeClient.onPermissionRequest`, which is what the WebView asks when a
  page requests a camera. Without it the request is denied silently.

If permission is refused, the page says so and offers entering the colours by
hand, so the app stays useful.

## Layout

```
app/src/main/
  java/dev/apps/collection/MainActivity.java   the WebView host
  AndroidManifest.xml                          permissions and the launcher entry
  res/values/                                  name, colours, dark theme
  res/mipmap-*/                                launcher icons (generated)
build.gradle                                   SDK levels, signing, asset staging
```

Icons are generated by `tools/make-icons.py` from the same designs as the web
icons, so the phone icon and the browser icon cannot drift apart. The version
comes from `release/VERSION`.

Signing is covered in `release/README.md`.
